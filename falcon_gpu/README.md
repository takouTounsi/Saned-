# Falcon GPU worker

The single local launcher starts this persistent OCR worker on `127.0.0.1:8002` when an NVIDIA GPU is detected. Its `.venv` can reuse compatible host packages, but installs CUDA PyTorch in the worker when the host has no PyTorch or its version is incompatible. The worker requirements include FastAPI, Uvicorn, and Pillow so it also starts when these are absent from host Python. The scanner stays in its own `.venv` and calls the worker over loopback HTTP; the application backend stays separate.

Run `python scripts/start_local.py` from the repository root. On a GPU computer, verify `http://127.0.0.1:8002/health` reports `device: cuda:0`. The scanner's `http://127.0.0.1:8000/api/health` reports `ocr_engine: falcon_http` because it uses the local worker. On a computer without a usable GPU, the launcher skips this worker and the scanner selects EasyOCR.

The Falcon model is downloaded to the Hugging Face cache on first use. By default this uses C:. Use `python scripts/start_local.py --hf-home X:\Inclusa-hf-cache` if another drive has more free space. The launcher checks for at least 3 GB free in the selected cache location before starting the worker. A local model directory can be supplied with `FALCON_MODEL`; the worker never downloads a model into the repository.

The current Falcon model code imports `AuxRequest` from PyTorch FlexAttention. That symbol is present in PyTorch 2.9 and absent in 2.8 and older. On Windows the worker therefore uses CUDA PyTorch 2.9.1, matching torchvision 0.24.1, and Triton Windows 3.5.0. The launcher installs this GPU runtime into the worker `.venv` when needed, without modifying global Python. It pins Transformers 5.23.0 because the model tokenizer declares `TokenizersBackend`; the worker checks that tokenizer during startup. Model revision `0bc28f89c90fbe8bdb063097fab144d4ce4c19b5` is fixed for the model code. See the [PyTorch wheel matrix](https://pytorch.org/get-started/previous-versions/) and [Triton Windows compatibility table](https://github.com/triton-lang/triton-windows).

The PyTorch CUDA wheel for Windows and Python 3.12 is about 2.86 GB compressed and 4.2 GB unpacked. Pip needed more temporary space than the earlier 7 GB check allowed, so the launcher requires 10 GB free on the worker drive when installing PyTorch, after accounting for any wheel bytes still to download. It skips this large-wheel check when a compatible worker PyTorch is already installed. On this platform it saves incomplete downloads under `%LOCALAPPDATA%\Inclusa\wheels`, resumes them with HTTP Range on the next launch, and verifies the SHA-256 checksum published in the official PyTorch index before installation. It removes the completed wheel after the GPU runtime passes its check. Other Python versions use pip with a 300-second network read timeout and 10 retries. On Windows the launcher uses short TorchInductor and Triton cache paths in the user profile to avoid path-length errors during GPU compilation.

This service implements the image payload and response shape used by `ocr-scanner/app/pipeline.py` at `/v1/chat/completions`. It is bound to loopback by the launcher and has no authentication. It is intended only for local synthetic scans. One live GPU inference on a generated image returned `HELLO 123`; recognition quality on real documents has not been assessed.
